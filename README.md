# Aster Research

**A question in. Evidence out.**

[Public source repository](https://github.com/spak2005/aster-research) · [Open the public observatory](https://aster-research.vercel.app/) · [Start a local investigation](https://aster-research.vercel.app/#/start)

A bounded scientific research harness with evidence-linked, recorded playback. Its first supported investigation uses the real [TORAX](https://github.com/google-deepmind/torax) tokamak transport simulator to explore heating profiles at a fixed auxiliary-energy budget.

The product is the closed loop: propose a hypothesis, predict an outcome, run an experiment, inspect measured evidence, revise or verify, and preserve what happened. The 3D observatory replays real recorded radial temperature profiles; it does not run physics in the browser.

## Quick start: explore a recording locally

Requires Node 22.12 or newer and npm. No model login or Python simulator is required for playback.

```sh
git clone https://github.com/spak2005/aster-research.git
cd aster-research
npm ci
npm run dev
```

Open the URL printed by Vite. A production build is `npm run build`; `npm run preview` serves it locally.

## Run real research locally

Python 3.12, [uv](https://docs.astral.sh/uv/) and an authenticated [Cursor CLI](https://cursor.com/docs/cli/overview) are required for the supported proposer. Credentials stay in Cursor, outside the browser and recordings.

```sh
uv venv --python 3.12
uv pip install --python .venv/bin/python -r requirements.lock.txt
agent login
npm ci
npm run dev:all
```

The API binds only to `127.0.0.1:8765`; the Vite web app proxies `/api`. Use the site's local setup flow to start a bounded investigation. Only one investigation worker runs at a time. The public static site does not expose an unauthenticated compute service.

Scientific execution was measured on an Apple M3 Pro with 18 GB RAM using TORAX 1.4.3. See [feasibility measurements](docs/science/FEASIBILITY.md). Other operating systems have not yet been independently verified.

## Reproduce the demo and configure credentials

**Exact recorded demonstration (no API keys):** follow the playback quick start above, choose **Where should we heat a fusion plasma?** in the catalogue, and play or scrub the investigation. This loads the committed [v2 recording](public/recordings/torax-iterhybrid-fixed-energy-v2.json), not a newly generated run. Open the evidence panel to download its original solver outputs and decision summaries. Its refined gain is approximately 2.37%, below the predeclared 5% target: the outcome is inconclusive, not a breakthrough.

**Fresh investigation:** follow the Python/Cursor installation commands above, then optionally configure the environment before starting both services:

```sh
cp .env.example .env
# Edit .env if needed, then explicitly export it for the Python backend:
set -a
. ./.env
set +a
npm run dev:all
```

The backend does **not** automatically load `.env`. In the local site's **Start an investigation** flow, use the supported fixed-energy plasma-heating preset with a nine-experiment budget so verification has reserved slots. A fresh model-driven run is stochastic and need not reproduce the same proposals or result. The checked-in recording is the reproducible demo artifact.

No OpenAI, Anthropic, or xAI API key is required by this implementation. Fresh model calls use your authenticated Cursor CLI account and its available models/usage allowance; run `agent login` locally. Do not put login tokens in the frontend or recordings. The recorded study used `cursor-grok-4.6-high-fast`; if unavailable on your account, select an available CLI model through `RESEARCH_MODEL` and expect different proposals.

| Environment variable | Purpose / default |
| --- | --- |
| `RESEARCH_MODEL` | Cursor model identifier; `cursor-grok-4.6-high-fast` |
| `CURSOR_AGENT_BIN` | Cursor CLI executable; auto-detected `agent` |
| `JAX_PLATFORMS` | Simulator compute backend; defaults to `cpu` |
| `XLA_PYTHON_CLIENT_PREALLOCATE` | JAX memory preallocation; defaults to `false` |
| `HARNESS_RUNTIME_DIR` | Optional experiment-output directory; defaults to repository `runtime/` |
| `RESEARCH_PROPOSER_CWD` | Optional proposer working directory; defaults to repository `runtime/proposer/` |

See the committed [sample environment file](.env.example). All these overrides are optional; playback requires none.

## Data, synthetic data, and provenance

- **Simulation-generated data, not reactor measurements:** the bundled temperature profiles, energy metrics and NetCDF files were generated by local TORAX 1.4.3 executions. No external experimental dataset or private user dataset is needed for the demo; no model was trained for this project.
- **Scenario origin:** adapted from Google DeepMind's [TORAX ITER-hybrid predictor-corrector example](https://github.com/google-deepmind/torax/blob/main/torax/examples/iterhybrid_predictor_corrector.py). Our frozen scenario uses constant transport, fixed density/current, and a one-second horizon with 51 MW auxiliary heating (51 MJ). Exact implementation: [executor](services/research/executor.py); assumptions and upstream attribution: [scientific provenance](docs/SCIENTIFIC_PROVENANCE.md).
- **Recorded investigations:** [catalogue](public/recordings/index.json) contains v2 (the featured eight-experiment adaptive study), v1 (the earlier six-experiment study), a deterministic nine-experiment reference, and a baseline-only snapshot. The reference is explicitly non-agent research, not a general benchmark proving agent superiority.
- **Audit trail:** recordings link to raw NetCDF solver outputs and saved proposer decisions under `public/recordings/`. Metadata captures software/settings and artifact hashes. Run `python3 scripts/check_public.py` to check linked artifacts and hashes.
- **Hand-authored synthetic fixtures:** contract/UI tests contain development examples; they are not scientific evidence and are not advertised as recorded investigations. The 3D torus is a schematic mapping of real recorded radial profiles, not simulated 3D turbulence.

## Verify evidence

```sh
npm run test:contracts
npm run check
.venv/bin/python -m unittest discover -s tests/research -v
python3 scripts/validate_recording.py your-recording.json
python3 scripts/check_public.py
```

The final command checks every public recording, linked evidence artifact and available SHA-256 hash. Development fixtures live outside public assets and cannot pass public-recording validation.

## Scope and scientific limits

This is one working adapter, not arbitrary research automation. The scenario uses constant transport, frozen current/density and a one-second horizon. A candidate improvement is evidence within this numerical scenario, not a reactor prediction or new physics claim. Refinement is not experimental validation. Initial stored plasma energy means a short-run fusion/input ratio is not a reactor power-balance result.

## Tech stack and architecture

| Component | Technology |
| --- | --- |
| Website and playback | React 19, TypeScript, Vite 7 |
| 3D visualization | Three.js, React Three Fiber, Drei |
| Local research API | Python 3.12, FastAPI, Uvicorn |
| Scientific execution | TORAX 1.4.3, JAX; NetCDF evidence |
| Hypothesis proposer | Authenticated Cursor CLI; Grok model in the recorded study |
| Public hosting | Vercel static frontend; research execution stays local |

```text
Research question → proposer → validated experiment → TORAX → raw NetCDF
                      ↑                                  ↓
                 prior evidence ← metrics and verification
                                      ↓
                              append-only events
                                      ↓
                          static 3D research replay
```

TORAX and its contributors provide the physics simulator. React, Three.js, React Three Fiber and Vite provide the interface. Aster records concise decision summaries, not private model chain of thought. See the upstream projects for their licenses.

## Known limitations and next steps

**Current limitations:** only the TORAX heating adapter is implemented; the public site is recorded-only. Fresh runs need a local Python environment, Cursor authentication and model availability, and run sequentially. Numerical refinement is not experimental validation; the simplified scenario and short horizon do not establish real-reactor performance. A single small deterministic reference does not establish that the AI is better than ordinary optimization. Fresh proposals are nondeterministic, and platforms beyond the tested Mac have not been independently verified.

**Next steps (planned, not shipped):** add a second scientific adapter to test portability; evaluate learned transport and longer-horizon scenarios with domain experts; run repeated equal-budget search comparisons across seeds; strengthen matched perturbation/uncertainty checks; and add authenticated hosted workers with job limits so researchers can launch runs without local setup. See the [adapter guide](docs/ADAPTER_GUIDE.md) for the current integration contract.
